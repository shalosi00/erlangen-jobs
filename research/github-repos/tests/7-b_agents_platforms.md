## Per-repo notes

### 1. career-ops-hq/career-ops (~74k★ context; last commit 2026-10-11)
- MIT (c) 2026 Santiago Fernández de Valderrama. 104 MB checkout; ~200 root `*.mjs` scripts; docs de/es/fr/+16 languages.
- **Architecture** (ARCHITECTURE.md): three principles — local-first, AI-agnostic, human-in-the-loop (never submits applications).
  - "Brain" = Markdown prompt files `modes/*.md` (A–H evaluation blocks, 1–5 scoring, archetype detection), executed by whatever AI coding CLI is present (Claude Code, Codex, OpenCode, Gemini, Qwen, Grok, Antigravity) or standalone eval runners (`gemini-eval.mjs`, `ollama-eval.mjs` local, `openai-eval.mjs` any OpenAI-compatible endpoint incl. OpenRouter/DeepSeek/Ollama).
  - Discovery = `scan.mjs` + `providers/` — **118 provider modules, all zero-token no-auth public sources**; auth-gated sources deliberately out of core (plugin layer, opt-in Apify). Output → `data/pipeline.md`.
  - Files are canonical, SQLite only a derived index; system/user file separation enforced by `DATA_CONTRACT.md` + CI guards; self-updater that never touches user data; optional Go TUI dashboard; 500+ CI checks incl. ATS SSRF-hardening suite (`_ip-guard.mjs`, `_safe-url.mjs`, `_trust-validator.mjs`).
  - Liveness gate: `check-liveness.mjs` verifies a posting is still open (zero-token) before it costs an evaluation.
- **Boards**: 30+ ATS (Greenhouse, Ashby, Lever, Workday, BambooHR, Teamtailor, Breezy, SmartRecruiters, SuccessFactors, Personio, SoftGarden, Phenom, iCIMS, Taleo, Oracle/Radancy, Eightfold, Avature, jazzHR, Jobvite, Rippling, SAP CSOD…), boards (Arbeitnow, Jobicy, RemoteOK, Remotive, WWR, HN "who's hiring", TheMuse, builtin, Himalayas, JustJoin, NoFluffJobs, 4dayweek…), single-company modules (Amazon, IBM, Alibaba, Tencent, Meituan, **Deutsche Bahn** (Avature via db.jobs SSR endpoint), **Heckler&Koch**, **Rheinmetall**), VDAB (BE), JobStreet/ITViec/CareerViet etc.
- **Germany**: first-class. `providers/arbeitsagentur.mjs` (265 lines) hits **exactly our endpoint** `https://rest.arbeitsagentur.de/jobboerse/jobsuche-service/pc/v6/jobs` with `X-API-Key: jobboerse-jobsuche`; config block per search profile (`keywords/wo/umkreis/days/size/remoteNationwide/remoteMatch/remoteMaxPages`). Their version-skew notes match and extend our 2-a findings: v4 search+detail 404 since 2026-08-04 (#2494), v5 too; v6 keeps was/wo/umkreis/veroeffentlichtseit/angebotsart/homeoffice/page/size but renamed response fields (they read `stellenlokationen[].adresse` — same accessors we use). Notable: in v6 the detail **no longer serves `homeofficetyp: VOLLSTAENDIG`** to this key, so they fall back to a server-side `homeoffice=nv_true` query + title check for remote detection.
- **Credentials**: none needed for scanning; LinkedIn appears only as (a) manual connections-CSV export cross-reference (`docs/LINKEDIN_JOIN.md`) and (b) `contacto` mode drafting a ≤300-char message for you to send — **no login scraping, no cookies**.
- What to ADOPT: BA-v6 provider config schema + remote detection modes; liveness-before-eval; provider = one file + registry pattern; seen/dedupe/tracker markdown-file conventions; SSRF guard layer. What to BORROW: A–H evaluation prompt structure as a rubric for our LLM scorer; RUNNING_ON_A_BUDGET/FREE_TIER model-rotation idea. SKIP: the Node/CLI-orchestration shell itself (we're Python+cron), Apify plugin, dashboard.

### 2. DaKheera47/job-ops (~4k★ context; last commit 2026-10-06)
- **License is NOT MIT**: AGPL-3.0 **+ Commons Clause** ("no Sell … for a fee or other consideration") — restrictive both ways (copyleft + non-commercial).
- Self-hosted: `docker compose up -d` → Next.js dashboard on :3005, single main container + volumes (codex-home, tectonic-cache for LaTeX PDFs). Onboarding wizard; 800+ users claim.
- Data flow: Search (extractors) → AI score 0–100 vs profile → tailor CV (local PDF or Reactive Resume API) → track (Gmail OAuth watches recruiter replies: interview/offer/rejection phrases auto-update status). Explicitly **no auto-apply** ("recruiters can tell … you get blacklisted").
- Sources (13 extractors + 3 career-boards): LinkedIn/Indeed/Glassdoor via **Python `jobspy` subprocess** (spawn python3, `JOBSPY_SITES=indeed,linkedin,glassdoor`), Adzuna API (country incl. germany), Hiring Cafe, startup.jobs, Working Nomads, Gradcracker (UK), **UK Visa Jobs with stored email/password** (`UKVISAJOBS_EMAIL/PASSWORD`, headless browser), Seek via paid Apify, WUZZUF/Khamsat (EG), jobindex (DK), naukri (IN), golangjobs, fiveamsat, freehire; company boards BambooHR/Greenhouse/Workday.
- Keys: `MODEL` (any of Atlas Cloud/Codex local/OpenAI/Anthropic/GLM/Gemini/OpenRouter/Requesty/Ollama), ADZUNA_APP_ID+KEY, APIFY_TOKEN, GMAIL OAuth pair, RXRESUME_API_KEY, UKVISAJOBS creds; BASIC_AUTH for the dashboard.
- **Germany**: no BA, no XING, no StepStone. Adzuna-DE yes; jobspy LinkedIn/Indeed/Glassdoor would return DE results but sits behind anti-bot (our 2-b: Indeed DE 401 wall, LinkedIn Akamai; jobspy's LinkedIn path is ToS-violating and IP-ban-prone — the repo itself is scraping-dependent).
- Verdict: SKIP as a base (license + stack weight + scraping dependency + Gmail OAuth complexity). BORROW: Gmail reply auto-detection mapping (interview/offer/rejection phrase lists) for our tracker; extractor-isolation pattern (each source its own service with its own retry/test); "one search across every board, still apply yourself" positioning.

### 3. jutt7/JobHunter (~1★, pushed daily — last commit 2026-10-11 "update seen jobs [skip ci]")
- MIT (c) 2026 Muhammad Awais Gondal. 2,036 lines Python, deps only `requests`, `openai`, `python-dotenv`. Runs **entirely on GitHub Actions free tier** (daily 05:00 UTC cron + workflow_dispatch); `seen.json` committed back with rebase-retry loop.
- **BA API usage — full read**:
  - Search: `GET https://rest.arbeitsagentur.de/jobboerse/jobsuche-service/pc/v6/jobs`, header `X-API-Key: jobboerse-jobsuche` (no signup; same public key we found).
  - Params: `was`, `wo`, `umkreis` (default 25), `veroeffentlichtseit` (DAYS_BACK=3), `size` (50), `page=1`, `angebotsart=1` (regular employment only), **`pav=false`** (excludes private placement agencies — neat filter we hadn't used), optional `arbeitszeit=ho/vz/tz` joinable by `;`.
  - Detail: `GET .../pc/v4/jobdetails/{base64(refnr)}` — they document that v2/v5/v6 detail paths return 403, v4 is the only working one; refnr must be **base64-encoded**. (Corroborates our 2-a detail_v4 findings; matches career-ops's "v4 404 as of 2026-08" only partially — career-ops says v4 *search* 404s; JobHunter shows v4 *detail* still works. Both can be true: v4 search dead, v4 detail alive.)
  - Response accessors: v6 names `referenznummer`, `stellenangebotsTitel`, `firma`, `externeURL` (preferred over BA detail page — "about 1 in 9" adverts carry an employer URL), `stellenlokationen[].adresse.{plz,ort,region}` (region enum "NORDRHEIN_WESTFALEN" → title-cased). Description fields fallback chain: `stellenangebotsBeschreibung` → `stellenbeschreibung` → `arbeitgeberdarstellung` → `beschreibung`; HTML stripped with stdlib HTMLParser, 6,000-char cap.
- **LLM scoring** (scoring.py): OpenAI API, default model `gpt-5.6-luna` (env `OPENAI_MODEL`; docstring claims vs gpt-4o-mini on 20 real postings: Spearman 0.78 rank agreement, +1.5 score inflation, more specific reasons), `response_format={"type":"json_object"}`, strict `{"score": 0-10, "reason": "..."}`, description capped at 4,000 chars, `max_completion_tokens=2000` for gpt-5 family (with the empty-response-on-reasoning gotcha documented), gpt-4 family gets `max_tokens=150`. Prompt: strictness anchor ("a 10 is rare"), weighs seniority/stack/location-language; if description missing → score conservatively on title and say so.
- **Pipeline order**: fetch all profiles → drop seen (seen.json, keyed company + gender-neutralised title + PLZ, *not* URL/date because BA refreshes dates) → dedupe (interleaved round-robin across profiles) → free regex title filter (`TITLE_INCLUDE`/`TITLE_EXCLUDE` re.X, strips "(m/w/d)" and parenthesised seniority — documented German-title edge cases like `\bdual` needing word boundary to not kill "Individualsoftware-Entwickler") → budget cut (`MAX_JOBS_TO_SCORE=40` LLM calls/run) → fetch advert bodies only for survivors → LLM score → `MIN_SCORE=6` threshold → TOP_N=15 digest → Telegram and/or Gmail SMTP; **marked seen only after ≥1 successful send** (failure retries next run).
- DE specifics: `PLZ_PREFIX_ALLOWLIST` (e.g. ["67","68","69"] example), German+English keyword profiles, currently frontend/fullstack-focused (their CV), relocate-anywhere default.
- Ops details: CV injected via `CV_TEXT` secret (fails fast if only the `# TEMPLATE` placeholder present); `VERIFY_SSL=false` escape hatch; standalone dev probes (`probe_detail.py`, `check_description.py`, `ab_models.py`); **38 offline tests passed in 1.3 s** in our sandbox (dedupe collision, umlaut folding "the German way", regression cases for title filter).
- **Comparison vs our BA v6 findings (2-a)**: endpoint, header, param names, v6 field names, externURL preference — all consistent with what we validated. Three things they have that our notes lacked: (1) `pav=false`, (2) `angebotsart=1`, (3) base64-refnr v4-detail recipe + explicit version map (v4 search dead / v4 detail alive / v6 search alive / v6 detail 403). One thing we knew that they don't use: EURES, Arbeitnow, Adzuna, ATS feeds — their `sources.py` FeedSource abstraction (fetch/describe) is explicitly built to add them.
- Verdict: **the single most relevant repo — it is our planned pipeline at 2k lines, MIT, already working.** ADOPT wholesale as reference implementation (or fork the dedupe/filter/budget/seen-persistence layer into ours); swap their CV/keywords for our FISI/Erlangen profile; add our Arbeitnow/Adzuna/EURES/ATS-feed sources via their FeedSource interface.

## Cross-cutting takeaways for our Python+cron toolkit

1. **Our BA v6 findings are now triple-corroborated** (our 2-a tests + career-ops provider + JobHunter client). Also add to our notes: `pav=false` (exclude private agencies), `angebotsart=1`, `arbeitszeit=ho;vz` combos, v4-detail-only + base64 refnr, and career-ops's warning that v6 stopped serving `homeofficetyp` (remote must be detected from text/title, or via `homeoffice=nv_true` query).
2. **Nobody in this cohort is DE-complete**: the only two repos that touch arbeitsagentur are career-ops (scan layer only) and JobHunter (whole pipeline). XING/StepStone appear in none — consistent with our 2-b verdict that those need SSR-parsing/ATS-feed workarounds, which is our differentiator.
3. **Consensus architecture** worth copying: fetch → dedupe (stable key, not URL/date) → free regex pre-filter → budget-capped LLM score (strict JSON, cheap model) → threshold → digest; mark-seen only after successful delivery; liveness check before spending eval tokens.
4. **License trap avoided**: job-ops (AGPL+Commons Clause) and the SaaS pinloop are unusable as bases; career-ops/JobHunter/jobsync/JobNavigator are MIT.
5. **Red-zone patterns to avoid** (all present in the cohort for a reason — they work in the US): logged-in LinkedIn cookie automation (JobNavigator), jobspy LinkedIn/Glassdoor scraping (job-ops, JobNavigator), credentialed board logins (job-ops UKVisaJobs). Our green/yellow source set (BA, EURES, Arbeitnow, Adzuna, ATS feeds, XING-SSR-logged-out, LinkedIn-guest) needs none of it.
